# ИИ-ВЕКТОР — передача MVP разработчикам

## Что это

Рабочий прототип аналитического сервиса для формы 1-МСП. Он импортирует
локальные Excel-книги, сохраняет происхождение каждого факта, рассчитывает
сравнения детерминированно и использует LLM только для перевода естественного
вопроса в проверяемый план запроса.

Требования и исходный замысел подробно описаны в:

- `REAL_MVP_IMPLEMENTATION_BRIEF_ИИ-ВЕКТОР.md`;
- `FRONTEND_BRIEF_ИИ-ВЕКТОР.md`.

## Что уже работает

- импорт общероссийских и региональных книг `.xls`/`.xlsx`;
- адаптация разных схем формы 1-МСП;
- показатели по графам, территории, периоды, группы МСП и строки ОКВЭД;
- сравнения периодов и регионов с проверяемыми источниками;
- вопросы о доступных периодах, регионах, налогах и ОКВЭД;
- продолжение диалога в рамках `conversation_id`;
- планирование через Z.AI/GLM с детерминированным fallback;
- генерация отчёта 1-МСП по контрольному шаблону Word.

## Что не входит в безопасный архив

По умолчанию handoff-архив не содержит:

- `.env` и API-ключи;
- `rd/` с исходными Excel/Word-файлами;
- `var/` с SQLite, журналами и созданными отчётами;
- `.venv`, `node_modules` и `dist`.

Это сделано намеренно. Перед передачей исходных данных необходимо отдельно
подтвердить права на их распространение. Разработчикам можно передать данные
другим защищённым каналом или смонтировать их локально в `rd/`.

## Локальный запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
npm ci
cp .env.example .env
AI_VECTOR_PYTHON="$PWD/.venv/bin/python" ./run_mvp.sh
```

Frontend: `http://127.0.0.1:4173`

Backend: `http://127.0.0.1:8000`

Без ключа LLM приложение использует детерминированный разбор. Для GLM нужно
локально заполнить `ZAI_API_KEY` в `.env`; этот файл не коммитится.

## Размещение данных

Ожидаемая структура задаётся в `.env.example`:

```text
rd/
├── 1_msp_db/   # исторические общероссийские и региональные книги
└── AutoMSP/    # контрольная пара, Коды.xlsx и template.docx
```

Если данных нет, frontend и backend запускаются. Часть интеграционных тестов
пропускается при отсутствии книг, но тесты сертификации и другие проверки
импортированного каталога могут требовать также заполненную SQLite-базу.
Полный набор тестов нельзя считать автономным без локальных данных.

## Проверка

```bash
PYTHONPATH=. python -m pytest -q
npm test
npm run build
```

Полноценная проверка импорта и отчёта требует каталога `rd/`.

## Git-передача и состояние проверок (21 октября 2026)

В исходном каталоге отсутствовала `.git`, поэтому для передачи создан новый
репозиторий с веткой `main`. Прежняя история коммитов не восстановлена.

В репозиторий входят код, тесты с эталонными числами, тестовые корпуса,
описания требований, зависимости, скрипты и `.env.example`. По согласованию
эталонные числа в тестах сохраняются. Исходные Excel-книги не передаются.
Каталоги `rd/`, `var/`, `artifacts/`, `handoff/`, окружения, сборки и `.env`
исключены; Excel-файлы и базы исключены также за пределами этих каталогов.

Проверки перед первым коммитом:

- `npm test -- --exclude 'handoff/**'`: 31 тест пройден;
- `npm run build`: успешно;
- полный Python-набор в отдельной копии без `rd/`, `.env` и локальной базы
  не проходит: ряд проверок требует импортированных фактов и регионального
  каталога. Это известное ограничение передачи без данных, а не подтверждение
  успешного прохождения backend-тестов.

Рекомендуемые первые задачи разработчиков: выделить автономные тесты с
синтетическими данными, явно пометить проверки с зависимостью от локального
каталога и заменить машинные пути в скриптах запуска. Для полного анализа
нужно отдельно предоставить разрешённые данные и выполнить их импорт;
пустая SQLite-база не заменяет импортированный каталог.

## Известные ограничения MVP

- чаты и проекты сохраняются в SQLite; выполнение фоновых аналитических
  запросов зависит от одного процесса backend;
- SQLite и локальная файловая система не рассчитаны на многопользовательский
  production;
- нет аутентификации и ролевой модели;
- 23 повреждённые региональные OLE-книги за 2022 год остаются в карантине;
- каталог и API требуют отдельного production-дизайна, мониторинга и миграций;
- LLM может быть недоступна или ограничена rate limit, поэтому числовые ответы
  всегда должны сохранять детерминированный fallback.

## Контрольные вопросы для демонстрации

```text
Для какого периода можно сравнить поступления МСП по Калининграду и Москве по НДС?
Сравни поступления по спецрежимам в Калининградской области и Москве за I квартал 2025 и I квартал 2026.
Какие регионы доступны?
Какие налоги и показатели доступны?
Какие коды ОКВЭД доступны?
```

Ожидается, что интерфейс покажет распознанный показатель и графу, периоды,
территории, ответ и происхождение использованных значений.
